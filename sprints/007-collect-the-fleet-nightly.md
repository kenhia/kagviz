# Sprint 007 — collect the fleet, nightly

korg:1620 · covers #1612 (fleet transcript collection: live mirrors and the
nightly timer), #1613 (derive stage and the cross-host session browser)

## Goal

The CLI prunes `~/.claude/projects` on a ~30-day window, and a session
vanished from under a corpus sweep while it was running (sprint 003). Every
report kagviz can make today is a thing you can make for a month. Review 006
named collection the priority for exactly that reason: without it there is
eventually nothing to browse, and the app the roadmap points at is only as
good as the data under it.

The design was already written (review 006, thread 1). This sprint's job was
to build it, answer the three questions the review left open, and find out
what the design had not seen.

## What the design had not seen

**copyparty's `run.sh` on kai is generated.** The review said serving was "a
one-line change to its `run.sh`". The file carries a `GENERATED by k-homelab
recipes/copyparty — do NOT edit on the host` banner: since k-homelab sprint
038 (2026-08-23, the day before the review) both `run.sh` and the unit are
rendered from `manifests/kai.yml`, `--check` diffs the installed copies
against fresh renders, and the next `bin/apply` reverts a local edit. So the
serving change is a **manifest edit in `kubs0:k-homelab`** plus
`bin/apply kai copyparty` — one cross-repo change, made through kaed, recorded
in k-homelab's changelog. `ReadOnlyPaths` on the unit is derived from the
volume list there, so the kernel backstop covers the new tree without a
second declaration.

**cleo's sftp root is `/C:/Users/kenhi`.** `ls C:/Users/kenhi/.claude/projects`
re-roots to `/C:/Users/kenhi/C:/Users/kenhi/…` and fails; the path form is
`.claude/projects`, relative. rclone's sftp backend also runs a shell-type
probe on connect that assumes a POSIX or PowerShell shell it can execute
commands in; `shell_type=none` skips it, and a copy needs neither.

## The three open questions, answered

| question | answer | why |
|---|---|---|
| rclone vs plain sftp for cleo | **rclone** | Incremental by size+mtime, never deletes, writes each file to a temp name and renames it — so a reader never sees a half-copied transcript. `scp -r` would re-copy ~120 MB nightly and rewrite every file in place. Installed user-scope into `~/.local/bin` from the official zip (v1.75.0): Ubuntu's package is 1.60, which predates the temp-then-rename default. A recorded machine change. |
| mtime vs content hash | **content hash** | sha256 over the transcript and each sidecar (name, length, bytes). A resumed session appends and a re-copy touches; only the first should re-derive. Tested: rewriting identical bytes does not change the digest, an appended record does, a new sidecar does. |
| `kagviz index` subcommand vs script | **subcommands** — `derive` and `index` | They are the extractor and renderer applied to a tree, they carry the version stamp, and they are unit-tested. Only the host pulls — ssh, rsync, rclone, which hosts exist — are shell (`collect/sync.sh`). |

## What shipped

**`collect/sync.sh`** — one host at a time, each independently: kai by local
rsync, kubs0 by rsync over ssh, cleo by rclone over sftp (host, user and key
read out of `ssh -G cleo` at run time, so `~/.ssh/config` stays the single
source). No `--delete` anywhere, on purpose. One cheap `ssh … exit` before
any transfer classifies a sleeping host as `unreachable` — a normal night,
exit 0 — as distinct from `failed`, which is a host that answered and then
broke, or a missing tool, and exits 1 so the unit shows it. rsync's exit 24
(files vanished mid-transfer) is `ok` with a note: that is what a
self-pruning source does. Every run writes `sync-status.json` and appends a
line per host to `sync.log`.

**`kagviz derive`** (`src/derive.rs`) — for every `<live>/<host>/projects/`,
every session: digest the source, skip it if `state.json` records the same
digest *and* the same kagviz version and both outputs exist, otherwise count
it and write the facts (the same bytes `show --json` prints, newline
included, so a derived facts file diffs clean against a baseline) and the
report. `state.json` is written after each host so a run that dies keeps
what it did. Then `sessions.json`, `index.html`, `META.json`. Every file goes
through a temp name and a rename. `--label` is accepted and the cache lives
in `derived/labels/`, never in a mirror; the timer does not pass it yet.

**A kagviz upgrade regenerates everything without being asked.** `build.rs`
stamps the binary with its commit (`0.1.0 (a1b2c3d)`); a session whose
recorded kagviz differs from the running one is re-derived. A changed
extractor is changed facts. `--force` does it on demand.

**`sessions.json`** — a second contract, documented beside the facts in
`docs/facts-contract.md`. One row per session across hosts, every figure
copied or summed from that session's facts, `host` and the state fields
added, optional fields **absent rather than null** from day one. Sorted
newest first, then host, then id, so the file is byte-identical when nothing
changed.

**`index.html`** — the browse page: a table newest-first with host, project
(`cwd`), what (the model-written headline marked *written*, else the opening
prompt), active with wall beneath it, prompts, tools with failures and agent
count beneath, files with the opaque count beneath, and links to the report
and the facts. Above it, the sync line: which hosts the last run reached —
"cleo — not reached" in the place a count would be. Self-contained by the
same test the report has: no scripts, no fetches.

**`collect/kagviz-collect.{service,timer}`** — a user unit on kai at
`04:00` local, which is Pacific across DST; `Persistent=true`; `PATH` set to
include `~/.local/bin` so rclone is found under the timer (kfdc's `claude`
trap). `just collect-install` builds the release binary, copies the units,
enables the timer. `just collect`, `collect-sync`, `collect-derive`,
`collect-status`, `collect-run` beside it.

**Serving** — a `/kagviz` volume over `live/derived` declared in
`manifests/kai.yml` and applied with `bin/apply kai copyparty`. Reports carry
session content and copyparty has no accounts; tailnet-only is the access
control, which is the boundary Ken already accepted for `~/src` on the same
viewer, and it is now written down in `docs/collection.md`.

Not touched: the pinned `corpus/` and `baselines/`; `live/<host>/projects`
by anything in kagviz; `kagviz sessions`, which still parses every transcript
to print a table — the browse surface has moved to `index.html`.

## Verified

- `just check` green: fmt, clippy `-D warnings` over `--all-targets`, 84
  tests (8 new, all in `derive.rs`): hosts are directories with `projects/`
  under them; the digest follows bytes not timestamps; derive writes once and
  again only on a byte change, rebuilds a missing output, honours `--force`;
  the label hook sees each summary; the index sorts newest first, links
  report and facts, says which hosts were reached, marks a failed one, emits
  no `null`; a headline is marked written; the index is self-contained; an
  empty tree still yields an index.
- **`derive` reproduces the pinned baseline byte for byte.** A live tree of
  symlinks to the three pinned corpora, derived to scratch and `diff -rq`'d
  against `baselines/<host>-2026-08-23/a8dad05`: kai 199/199, kubs0 93/93,
  cleo 113/113 **identical**, 0 skipped lines. So a derived facts file *is*
  `show --json`, and the regression check can run off `derived/` from now on.
- **The first real run**, 2026-08-25T03:44:59Z, from a clean
  `/ai-data/kagviz-data/live/`:

  ```
  kai    ok             254 file(s)    1s
  kubs0  ok             158 file(s)    1s
  cleo   ok             210 file(s)    4s
  cleo       115 session(s)    115 derived      0 unchanged
  kai        194 session(s)    194 derived      0 unchanged
  kubs0       93 session(s)     93 derived      0 unchanged
  index      402 session(s) → /ai-data/kagviz-data/live/derived/index.html
  kagviz   0.1.0 (d40f94f)  in 1.1s
  ```

  569 MB mirrored in six seconds; 402 sessions counted, rendered and indexed
  in **1.1 s**. The corpus sweeps that "take minutes" were paying for a
  process per session and a directory scan per process, not for parsing.
  facts = reports = mirror per host; `sessions.json` contains no `null`; 401
  of 402 rows have an `opened_by`, none has a headline (no `--label`).
- **Second run, nothing changed:** 402 unchanged, 0 derived, 0.3 s. The
  first row of the index was *this* session, mirrored mid-sprint; the next
  sync will re-derive exactly it, because its bytes will have changed.
- **The mirror is a superset of the corpus already.** 402 live vs 405
  pinned: kai has 194 live sessions against 199 pinned (five have been
  pruned at the source since the 23rd), cleo 115 against 113 (two new). Two
  days in, the source has lost sessions the pinned corpus still holds — the
  mirror, from tonight, stops that from happening again.
